# 위협 모델(Threat Model) — 금융/보안 기준

## 보호 대상(Assets)

- **거래소 API 키/시크릿** (최상위)
- 유저 자산/포지션/주문 상태
- 유저 트레이드 기록(민감한 금융 데이터)
- 구독 등급/권한(우선순위/AI 강도/기능 제한)
- 감사 로그(조작/삭제 방지 필요)

## 공격자 모델

- 외부 공격자: 계정 탈취, API 키 탈취, 주문/설정 변조
- 내부자 위협: 운영자/개발자에 의한 데이터 오남용
- 인프라 침해: DB 덤프 유출, 로그 수집 시스템 유출
- 3rd-party 위험: OAuth/SDK/패키지 공급망

## 핵심 보안 목표

- **키 비노출**: 서버 운영자도 “원문 키”를 조회/복구할 수 없도록 설계
- **테넌트 격리**: 유저 간 데이터 접근을 **DB 레벨에서 차단(RLS 등)**
- **아이템포턴시**: 중복 주문/레이스 컨디션 방지
- **감사 가능성**: “무엇을/왜/언제” 했는지 변경 불가능하게 기록
- **Fail-safe**: 불확실하면 자동매매 중단

## 주요 위협과 대응(요약)

- **API 키 유출**
  - DB at-rest 강력 암호화, 복호화는 주문 직전 메모리에서만
  - 로그/에러/트레이스에 키 출력 금지(전역 레드액션)
  - 키 재조회 UI/API 금지, 마스킹만 제공(****abcd)
- **권한 상승/구독 우회**
  - 기능 제한/AI 강도는 서버에서만 결정
  - 모든 요청에 정책 체크(미들웨어)
- **유저 간 데이터 노출**
  - Postgres RLS + `SET LOCAL app.user_id`
  - 서비스 계정이라도 RLS 우회 금지(운영/백업 경로 별도)
- **주문 중복/상태 불일치**
  - 분산락/아이템포턴시 키
  - 거래소 포지션 리컨실리에이션(재시작 복구)
- **데이터 조작/삭제**
  - 트레이드 이벤트 append-only 테이블(논리적 삭제 금지)
  - 감사 로그 WORM(Write Once Read Many) 지향
