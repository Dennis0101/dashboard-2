# API Key Vault 설계

## 요구사항(필수)

- **출금 권한 없는 키만 허용**
- 유저도 자신의 API 키를 “다시 볼” 수 없어야 함
- DB 저장 시 강력 암호화
- 복호화는 주문 실행 직전, 메모리에서만
- 로그에 API 키 절대 출력 금지
- UI/응답은 마스킹 형태(예: `****abcd`)만

## 저장 모델(권장)

`exchange_api_keys` 테이블에 다음을 저장한다.

- `encrypted_payload`: 암호문(키/시크릿/추가 passphrase 등을 JSON으로 묶어 암호화)
- `encryption_version`: 키 롤오버를 위한 버전
- `masked_hint`: 예) `****abcd` (원문 유추 불가)
- `created_at`, `revoked_at`

> 원문 키는 어떤 API로도 반환하지 않는다.

## 암호화 방식(서버)

- AES-256-GCM 같은 **AEAD** 사용 (기밀성 + 무결성)
- 마스터 키는 환경변수/시크릿 스토어에서 주입
- 가능하면 KMS(Envelope Encryption)로 발전 가능하도록 인터페이스화

## 복호화 제약

- API 서버는 기본적으로 “복호화 권한”이 없다(권장).
- Executor(주문 실행 워커)에서만 복호화 허용.
- 복호화 후 즉시 사용하고, 메모리에서 폐기(가비지 컬렉션 의존 최소화).

## 로깅/에러 처리

- 예외 메시지에 원문 키가 섞이지 않도록:
  - 입력 검증 단계에서 즉시 레드액션
  - 전역 로거에서 민감 필드(`apiKey`, `secret`, `passphrase`) 자동 마스킹
