# 시스템 아키텍처 (Mobile-First)

## 목표

- 모바일 앱은 **제어/시각화/설정/상태 확인**만 담당한다.
- 자동매매 로직 및 AI 판단, 주문 실행은 **서버에서만** 수행한다.
- “불확실하면 멈춘다” 원칙이 **코드/운영에서 강제**되어야 한다.

## 컴포넌트

### Mobile App (iOS/Android)

- 로그인(Apple/Google)
- 봇 상태/리스크/설정 제어
- 차트(캔들/하이켄/바) + 트레이드 마커/연결선 + PnL 표시
- 트레이드 타임라인/상세(“왜 진입/왜 청산”)

### API Server

- 인증/권한/구독 등급(Basic/Pro/VIP) 정책 “서버 강제”
- 유저 설정(거래소/심볼/레버리지/리스크 제한)
- 트레이드 기록/리포트/차트용 마커 데이터 제공
- 키 보관(암호화 at-rest, 마스킹 display)

### Executor (Order/Position Worker)

- 거래소 주문 실행(출금권한 없는 키만 허용)
- 포지션 상태 추적/복구(서버 재시작 포함)
- 주문 중복 방지(아이템포턴시/락)
- 리스크 가드레일(최대 손실/포지션 수/노출)
- AI 판단 결과를 그대로 “따르지” 않고, **거부/필터링**을 1차 목적에 둔다

### Data Store

- Postgres (권장): 트레이드, 설정, 구독, 감사 로그
- Redis(선택): 잡 큐, 락, 아이템포턴시 키

## 데이터 흐름(요약)

1) 앱 로그인 → 서버에 세션/JWT 확립  
2) 앱에서 “자동매매 ON” 요청 → 서버가 정책/리스크/상태 점검  
3) Executor가 시장데이터/AI/전략 신호 → **필터링** → 주문 실행(필요시)  
4) 모든 이벤트(진입/청산/거절/중단)는 트레이드 로그로 기록  
5) 앱은 차트/타임라인에 그 기록을 **증명 가능하게 시각화**
